# 网易云音楽 アーティスト・アルバム監視ツール · cloudmusic-artist-album-monitor

> このクローラーは自分のために書いたものです。気になるアーティストがどんどん増えていって、毎日一人ずつアーティストページを開いて、新曲やカバーがアップされていないか確認するのは本当に面倒でした。以前は bat ファイルで試してみたのですが、一瞬で大量のページが開いてものすごく重くなるし、BAN される可能性もあるし、CPU にも悪い。そこでこれを書きました（なぜ最初からクローラーを思いつかなかったんだろう、本当に自分は馬鹿だなあ）。

**Language**: [中文](README.md) ｜ [日本語](README.ja.md) ｜ [English](README.en.md)

---

## 何をするもの

`歌手配置.txt` に書いたリストを読み、网易云音楽（NetEase Cloud Music）の公開 API で
各アーティストの**全アルバム**を取得し、前回成功時のスナップショットと**アルバムID**で比較して、
**新着**と**削除（配信終了）**をログに追記します。

1 回実行する = 最新スナップショット 1 つ + 変化だけが書かれたログ 1 つ。
アーティストページを一人ずつ開いて確認する作業はもう要りません。

## 特徴

- 単一ファイルのスクリプト。`requests` のみ使用、同期・順次リクエスト（非同期もマルチスレッドも Selenium も使わない）
- 自動ページングで、そのアーティストの全アルバムを取得（Web 版の「最初の数枚しか出ない」制限やログイン要求に引っかからない）
- 新着判定は**アルバムID**基準。アルバム名の変更・リマスター・ジャケット変更を新着と誤判定しない
- 取得失敗やアーティストID無効のときは**絶対に古いスナップショットを上書きしない**（状態と失敗理由だけ更新）
- ネットワーク系エラーは自動リトライ。失敗後に再び成功したら、その間の新着を補記して `[恢复]`（復帰）を 1 行書く
- リクエスト間にランダムな待機を入れて、高頻度アクセスを避ける
- スナップショットはアトミック書き込み（一時ファイル → 置換）。途中で Ctrl+C しても JSON は壊れない
- 設定不要・DB 不要。データファイル 3 つはスクリプトと同じフォルダに置かれる

## 動作環境

- Python 3.x（開発・動作確認環境：Windows 10 + Python 3.14.4）
- `requests`

```bash
pip install requests
```

## 使い方

1. 依存関係をインストール：`pip install requests`
2. `歌手配置.txt` を編集し、1 行 1 アーティストで `アーティスト名 | アーティストID` を書く
3. 実行：

```bash
python 专辑监控.py
```

アーティストID は、アーティストページの URL `https://music.163.com/#/artist/album?id=53678173` に出てくる数字の部分です。
初回実行では取得した全アルバムが `[新增]`（新着）として記録されます。

## 設定ファイルの書き方

```text
LIMIT = 50            # 1 ページあたりの取得件数。省略可（既定値 50）

# アーティスト名 | アーティストID
花譜 | 32062601
理芽 | 47614811
```

- `#` で始まる行と空行は無視されます
- 書式が不正な行はスキップされ、コンソールに警告が出ます（実行全体は止まりません）
- 「アーティスト名」は表示とログ用です。名前を変えても新着判定には影響しません（判定はアルバムIDのみ）
- アーティストID が重複した行はスキップされ、その旨が表示されます

## データ取得元と判定ルール

Web 版の HTML にはアルバムデータが含まれなくなったため、BeautifulSoup での解析は行わず公開 API を直接呼びます。

```text
GET https://music.163.com/api/artist/albums/{アーティストID}?offset={offset}&limit={limit}
```

リクエストヘッダは一般的なブラウザの UA + `Referer: https://music.163.com/`、タイムアウトは 15 秒。
ページ間は 1.5〜3.5 秒、アーティスト間は 5〜10 秒のランダム待機を入れます。

- `code=200` かつ `artist` が非 null → 成功。`hotAlbums` から `id` / `name` / `publishTime`（ミリ秒タイムスタンプを `YYYY-MM-DD` に変換）を取得
- `code!=200` または `artist` が `null` → アーティストID無効。状態は `invalid`、**リトライしない**、古いスナップショットはそのまま
- `code=200`・`artist` 非 null だが `hotAlbums` が空 → アルバムなしとみなし、状態 `ok`、古いリストを空にする（失敗ログは書かない）
- ページング：`offset` は 0 から `+= limit`。取得件数が `limit` 未満になった時点で末尾とみなす（`limit` と同じときだけ次ページへ）
- ネットワーク系エラー（タイムアウト / 接続失敗 / 5xx）：2 回リトライ（間隔 2〜3 秒）。それでも失敗したら状態 `failed`、古いスナップショットは保持

## 注意点

- `专辑快照.json` と `监控日志.log` が唯一の履歴です。**スナップショットを消すと、次回実行で全アルバムが新着として記録し直されます**（消さないでください）
- 取得に失敗したときは古いリストがそのまま残るので、たまに実行しそこねてもデータは失われません。次に成功したときに自動で補記されます
- ログ内の失敗理由は 200 文字を超えると切り詰められます（全文は `专辑快照.json` に保存）
- アーティストが多いと 1 回の実行に数分かかります（待機はわざと入れています。短くしすぎないでください）
- 公開 API を読むだけで、ログインも音声ファイルのダウンロードもしません
